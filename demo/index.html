A region where only what is inside it changes

An ordinary rectangle drag over someone else's page: the DOM, the text, the images and the site's CSS are untouched, clicks and links keep working, and on pointer release the page returns to its original state. The demo uses the built package (../dist/index.js) as an external consumer — through the same public API that is available from npm.

Playground

This is the playground's surface and the target of element activation: the gesture starts only here. Everything inside is ordinary markup: text, a button, canvas, SVG, an image, a gradient, cards. The button inside the playground still clicks — the inversion does not intercept clicks.

Text

The region inverts whatever falls inside it: black text becomes white, the background becomes dark. Note that the layer itself copies nothing and filters nothing — it blends with the page through mix-blend-mode: difference, so the text stays live and selectable.

Different stacking contexts

The layer lives in the top layer, so neither the content's z-index nor the stacking contexts it creates get in its way. Check that on this very page: drag a region over these cards.

Connecting

Three ways below, all on the public v0.1 API. This page itself uses the first one.

1. Package (ESM)

import { visualRegion } from 'visual-region';

const region = visualRegion({ activation: 'element', surface: document.querySelector('#playground') });

2. CDN (IIFE, no build step)

<script src="visual-region.global.js"></script>
<script>
  const region = VisualRegion.visualRegion({ activation: 'modifier', modifier: 'alt' });
</script>

3. Markup (data-visual-region="invert")

import { autoInit } from 'visual-region';

autoInit(); // or import 'visual-region/auto' — the same thing, but at import time

A live example: this card is marked up with attributes and enabled through autoInit() when the page loads. Drag right inside it — persistent keeps the region after you release, and the next gesture replaces it.

The region is enabled by markup
data-visual-region="invert" data-activation="element" data-surface="self" data-persistent="true"

What is not inverted, and why

These are v0.1 limitations, not promises: each one is either measured or follows directly from how the top layer works. The full list is in the README (Known issues).

  • Anything that entered the top layer after our region. Order in the top layer is "last in, higher up". A dialog opened after the gesture began ends up above the layer; we do not fight over that order. — measured in three engines: the library does not lose its own layer (lost-top-layer does not arrive), the dialog is painted above the region, and the rest of the page under that same region keeps inverting.
  • Fullscreen. A fullscreen element is in the top layer too, and above our region as well.
  • Overlapping regions cancel each other out. Two inversions bring back the original: the semantics of nested regions are undefined in v0.1.
  • The region is anchored to the viewport, not to the document. With persistent the region stays in place while the content under it scrolls away.
  • Legacy mount: 'fixed'. Outside the top layer: it breaks on hostile transform/opacity/filter on html/body and on a high z-index in the content (measured). For environments without the Popover API only.
  • A 2 CSS-px fringe at the region's edge under a hostile html { transform } is not inverted in full. The interior itself is exact (maxErr = 0, inverted fraction = 1): that is the behaviour of edge rasterisation, not an inversion error. Measured at DPR=1 and DPR=2.
  • Touch input is off by default (touch: 'off'): v0.1 does not touch mobile scrolling or pinch-zoom. Turn on touch: 'surface' in the panel to drag with a finger inside the playground.

What v0.1 does not have

This demo's panel shows nothing that does not exist: effect is only invert, shape is only rect. There is no filter, circle, freehand, spotlight, theme or colorMap here — those values do not exist in the library.
